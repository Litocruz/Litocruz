Observo que Secure Boot está 100% desactivado en ese servidor.

Aquí tienes el análisis de por qué, basado en los comandos que ejecutaste:

ls /sys/firmware/efi (La Prueba Definitiva):

Resultado: No such file or directory

Observación: Esta es la evidencia más importante. La ausencia de la carpeta /sys/firmware/efi significa que el servidor no arrancó en modo UEFI. Arrancó en modo Legacy BIOS.

ls /sys/firmware/:

Resultado: acpi dmi memmap

Observación: Esto confirma lo anterior. El directorio existe, pero le falta la carpeta efi.

journalctl y dmesg:

Resultado: journalctl no devuelve nada. dmesg muestra que se cargó un certificado de SUSE (SUSE Linux Enterprise Secure Boot Signkey).

Observación: Esto puede ser confuso. La línea de dmesg no significa que Secure Boot esté activo. Solo significa que el kernel de SUSE que está cargado está firmado digitalmente y es capaz de arrancar en un sistema con Secure Boot. Sin embargo, como el sistema arrancó en modo BIOS, esta firma no se utilizó.

Conclusión: Dado que Secure Boot es una característica que solo existe en el modo UEFI, y este servidor arrancó en modo Legacy BIOS, Secure Boot no está (ni puede estar) activado.
